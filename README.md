# Smart Wardrobe

A mobile-first web app that puts your real wardrobe on a 3D avatar. You photograph your clothes, organize them, build outfits, and see each outfit on a static 3D model.

This is the **first milestone**:

> A user opens the app, sees a 3D avatar, changes its clothes, and saves the outfit.

It also includes the first slice of the wardrobe system: photo upload, a placeholder analyzer, user confirmation, and CRUD.

| Layer | Technology |
| --- | --- |
| UI | Flutter (Android, iOS, and web) |
| 3D | A small Three.js viewer served by the API and embedded by Flutter. It composites the avatar and garment GLBs |
| Backend | FastAPI, Pydantic, SQLAlchemy 2, Alembic |
| Database | PostgreSQL 16 (Docker Compose) |
| AI | Swappable service interfaces. Default is a local, no-ML placeholder |
| 3D authoring | Blender (offline). Sample assets are generated by a Python script |
| Storage | `StorageService` with `LocalStorage` (dev) and `S3Storage` (R2 / Supabase / S3) |

Everything is free and open source. No paid API is needed.

## Run it locally

Prerequisites: Flutter stable, Python 3.11+, Docker.

```bash
# 1. Configuration
cp .env.example .env

# 2. Database
docker compose up -d

# 3. Backend (http://127.0.0.1:8765, docs at /docs)
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8765

# 4. Flutter app, in a second terminal
cd app
flutter pub get
flutter run --dart-define=API_URL=http://127.0.0.1:8765
```

`flutter run` asks for a device. Use Chrome for the web app, or an Android or iOS simulator. Tap **Explore the demo wardrobe**, or create an account. Every new account starts with 9 sample pieces that have 3D models, plus one saved outfit.

The Android emulator reaches the API at `http://10.0.2.2:8765` instead of `127.0.0.1`. On a phone, use your computer's LAN address for `API_URL`.

The API serves the sample models at `/models` and the avatar viewer at `/viewer`. The viewer loads Three.js from jsDelivr, so the 3D scene needs a network connection.

### Regenerating the sample 3D assets

```bash
python blender/scripts/generate_sample_assets.py
```

This writes `models/avatar/base_avatar.glb` and 9 garments to `models/garments/`. The script uses only the Python standard library. Every asset shares one coordinate space (Y up, meters, feet at origin), so garments line up on the avatar with no runtime fitting. FastAPI serves that folder at `/models`.

## What works

- **Welcome, register, login, demo account.** JWT auth with bcrypt-hashed passwords.
- **Home.** Time-of-day greeting with your name, a 3D preview of your latest outfit, a wardrobe summary, and an AI Stylist placeholder.
- **Wardrobe.** Category filters and an image grid. Each card shows name, category, color, brand, size, and a 3D badge.
- **Add clothing.** Take or choose a photo, preview it, upload it (it's resized and thumbnailed), and run analysis. The analysis comes back as suggestions in a form you can edit; nothing is saved until you confirm.
- **Item detail.** Edit any field or delete the item.
- **Avatar Studio.** Rotate, zoom, and reset the camera. Choose a Top, Bottom, Outerwear, and Shoes item, or None for any slot. Save as a new outfit, or update a loaded outfit. An update sends only the slots that changed.
- **Outfits.** List, open in the studio, and delete.
- **Profile.** Optional body measurements and an avatar build preset (slim, average, or broad). These drive the avatar's scale through `GET /api/v1/avatar`.

### 3D performance rules (mobile)

- Only the GLBs for the current outfit are loaded, never the whole wardrobe.
- Each slot loads independently, so changing the shirt reloads only the shirt.
- When a garment leaves the scene, its geometry and materials are disposed and its cache entry is cleared.
- Rendering uses `frameloop="demand"`, so the scene redraws only when something changes.
- Pixel ratio is capped at 2, one shadow-casting light is used, and the environment is a CSS gradient instead of an HDRI.
- Each garment is about 20–50 KB and has no textures.
- An error boundary wraps each model, so one broken GLB can't crash the scene.

## Architecture

```text
app/ (Flutter)  ──HTTP /api/v1──>  backend/ (FastAPI)
                                    ├── PostgreSQL (SQLAlchemy + Alembic)
                                    ├── services/ai        ClothingAnalyzer, Segmentation, BodyAnalysis, Recommendation
                                    ├── services/garments  GarmentFitService, Garment3DProcessor
                                    ├── services/body      BodyProfile → avatar parameters
                                    ├── services/storage   LocalStorage | S3Storage
                                    ├── /models            sample avatar and garment GLBs
                                    └── /viewer            Three.js avatar scene embedded by Flutter
blender/  (offline)  ──GLB──>  models/
ai/       (offline)  model experiments and weights
```

### Replaceable pieces

| Concern | Interface | Current implementation | Swap by |
| --- | --- | --- | --- |
| Clothing recognition | `ClothingAnalyzer` | `LocalHeuristicAnalyzer` (dominant color only) | Add a class and set `CLOTHING_ANALYZER` |
| Storage | `StorageService` | `LocalStorage` | `STORAGE_BACKEND=s3` plus the `STORAGE_*` vars |
| Garment fitting | `GarmentFitStrategy` | `PredefinedScaleFit` (garment follows the avatar transform) | Pass a strategy to `GarmentFitService` |
| Photo to 3D | `Garment3DProcessor` | `UnavailableGarmentProcessor` (says so honestly) | `get_garment_processor()` |
| Avatar shape | `build_avatar()` | Preset plus height scale | Shape keys driven by `parameters` |
| Renderer | `AvatarStage` scene message | Three.js page at `/viewer` | Same message, different host |

AI output never overwrites what the user has confirmed. Analysis is stored in `ai_analysis` and shown as suggestions. A field changes only when the user saves the form. Body measurements follow the same rule: `BodyProfile.source` records whether values were entered manually or estimated.

A clothing item can exist without a 3D model: `glb_url` is optional, and `status` tracks `uploaded → analyzing → analyzed → processing_3d → ready | failed`. Items without a GLB appear in the wardrobe but not on the avatar.

### API (prefix `/api/v1`)

```text
POST /auth/register   POST /auth/login   POST /auth/demo   GET /users/me
GET|PUT /body-profile
GET|POST /wardrobe    POST /wardrobe/upload    GET|PUT|DELETE /wardrobe/{id}
POST /wardrobe/{id}/analyze
GET|POST /outfits     GET|PUT|DELETE /outfits/{id}
GET /avatar           POST /avatar/generate
POST /garments/{id}/process-3d    GET /garments/{id}/3d-status
```

Interactive docs: http://127.0.0.1:8765/docs

## Security notes

- Secrets live only in environment variables. `.env` is git-ignored, and `.env.example` documents every key.
- The Flutter app holds no secrets. It talks only to the backend through `API_URL`.
- Change `SECRET_KEY` and set `SEED_DEMO_USER=false` for any deployment that isn't local.
