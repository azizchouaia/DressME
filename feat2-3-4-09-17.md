# feat 2-3-4-9-17 · Module agents (M2, M3, M4, M9, M17)

Owner: BO1 / BO2 (Racem). Branch: `feat/m02-m03-m04-m17`.

Every module of this branch is reachable as an **agent**: another BO's agent (or the orchestrator) sends it a
message, it answers with a result. No LLM inside the agents: each agent wraps the module's real service, so an
agent call gives exactly the same result as the module's HTTP endpoint.

| Agent | Module | What it does | Actions |
|---|---|---|---|
| `m02_recommendation` | M2 | outfits for a day / occasion / mood / weather (pretrained OutfitTransformer + FashionCLIP) | `recommend`, `remix`, `complete`, `swap`, `score` |
| `m03_wear_log` | M3 | worn log, laundry / lent status, wear stats | `worn`, `unworn`, `posted`, `status`, `laundry_done`, `states`, `stats`, `history`, `forgotten`, `recap` |
| `m04_scheduler` | M4 | outfit of today / tomorrow, calendar, events, notifications | `today`, `tomorrow`, `approve`, `change`, `wear`, `week`, `calendar`, `event_add`, `event_delete`, `schedule`, `widget`, `notifications`, `notification_action`, `run` |
| `m17_capsule` | M17 | capsule wardrobe (integer linear programming) + month plan | `capsule`, `plan` |
| `m09_avatar_3d` | M9 | 3D avatar, pieces from photos sewn in 3D, outfits / animation as GLB | `render`, `pieces`, `wardrobe3d`, `outfit3d`, `set_body`, `items` |

Dependencies between agents (published in each card): M2 → M3 · M4 → M2, M3 · M17 → M2, M4.

## 1. The message

Request (same for every agent):

```json
{"action": "recommend", "user_id": "u1", "payload": {"context": {"occasion": "work"}}, "sender": "m06_smartbuy"}
```

- `action`: one of the agent's actions
- `payload`: exactly the payload of the module's HTTP endpoint for that action (see `modules/<m>/contract.py`);
  it is validated and missing fields get their defaults
- `sender`: who is asking (another agent's name, `orchestrator`, `http`)

Answer:

```json
{"agent": "m02_recommendation", "action": "recommend", "ok": true, "result": {"outfits": [...]},
 "mocked": false, "error": null}
```

An agent never crashes its caller: an unknown action or a failure returns `ok: false` with `error`
(for an unknown action, the list of valid actions).

Each agent also publishes a **card** (`agent.card()`): description, actions, the payload fields of each action,
and the agents it depends on. Other agents and the orchestrator read it to know what to ask.

## 2. Code

| File | Role |
|---|---|
| `backend/shared/base_agent.py` | team interface every agent implements (unchanged) |
| `backend/shared/action_agent.py` | `ActionAgent` (BaseAgent with actions), `AgentRequest` / `AgentResponse`, `langchain_tool()` |
| `backend/shared/agent_bus.py` | finds every `modules/*/agent.py`; `ask()`, `get()`, `directory()` |
| `backend/modules/<m>/agent.py` | the module's agent: its actions mapped to the module's service functions |
| `backend/modules/<m>/tool.py` | the agent as a LangChain tool (`tool`) for the orchestrator |
| `backend/api/routes/agents.py` | HTTP access: `GET /agents`, `POST /agents/{name}` |
| `backend/shared/test_agents.py` | tests (cards, envelope, errors, registry, agent-to-agent call) |

Mocks are respected: if `M02_USE_MOCK=true` (or the global `USE_MOCKS`), the M2 agent answers from `mock.py`
with `"mocked": true`, exactly like the HTTP endpoint.

## 3. How other BOs' agents reach ours

**Same backend (Python):**

```python
from shared.agent_bus import ask

res = await ask("m02_recommendation", "recommend",
                {"context": {"occasion": "work", "city": "Tunis"}, "options": {"n": 3}},
                user_id="u1", sender="m06_smartbuy")
if res["ok"]:
    outfits = res["result"]["outfits"]
```

Discovery: `from shared.agent_bus import directory; directory()` → the cards of every agent.

**Another service (HTTP):**

- `GET /agents` → cards of every agent
- `POST /agents/{name}` with the message above as JSON body

Example chain (tested): BO asks M9 for the user's pieces, then M2 for outfits made from them:

```python
items = (await ask("m09_avatar_3d", "items", user_id="me", sender="bo_x"))["result"]["items"]
res = await ask("m02_recommendation", "recommend",
                {"items": items, "context": {"occasion": "casual"}}, user_id="me", sender="bo_x")
```

## 4. How the orchestrator reaches them (owner: M6)

Nothing to wire by hand. `backend/orchestrator/registry.py` imports every `modules/<m>/tool.py` and uses its
`tool`. Each of our `tool.py` is:

```python
from shared.action_agent import langchain_tool
from .agent import agent

tool = langchain_tool(agent)
```

so the orchestrator LLM gets one tool per module, named after the agent (`m02_recommendation`, ...), with
arguments `action` (the description lists every action), `payload` and `user_id`, and the agent's description
to choose it. The LangGraph `ToolNode` calls the tool, which sends the message to the agent and returns the
answer dict. `orchestrator.registry.tool_names()` now lists our 5 modules.

## 7. BO1 / BO2 agents (LLM agents on top of the module agents)

Every BO idea now has an **idea agent** (`backend/bo/bo1_recommendations/agents.py`, `backend/bo/bo2_time/agents.py`)
and each BO has an **orchestrator agent**: `personalised_recommendations` (BO1) and `time_optimisation` (BO2).
They speak the BO8 protocol (`shared/agent_card.py`: `AgentCall` in, `AgentResult` out) and use the module
agents above as tools through the agent bus.

- **BO1 idea agents**: daily_outfit, rotation, forgotten, capsule, seasonal_refresh, avatar_preview, gap_filling,
  travel, style_insights. **BO2**: daily_plan, swap, laundry, event_looks, local_shops, photo_piece, declutter.
- **LLM**: one local model for all agents, Qwen2.5 3B served by Ollama (`shared/local_llm.py`,
  `LLM_LOCAL_MODEL`). Each agent sends its own prompt: the BO agent's LLM picks the idea agent, the idea
  agent's LLM picks the action + arguments (JSON mode), the tools do the work, the LLM writes the answer from
  the tool results. Keyword guardrails lock obvious choices. Core: `shared/idea_agent.py`.
- **No LLM for structured calls**: `payload = {"action": "swap", "args": {"slot": "shoes"}, "reply": false}`
  (app buttons, other agents, BO8) runs the action directly. Cross-BO: `"partner:agent.action"`.
- **Memory**: conversation + session blackboard (last outfit, shared by all agents of a session) and taste
  profile in `backend/.agent_memory/` (git-ignored, `shared/agent_memory.py`); wear history in M3.
